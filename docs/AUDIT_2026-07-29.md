## Premise verification and rejected phantom work

- Rejected/deferred “Mark launch or lifecycle green from this repository”: Rejected. Hosted health, applied edge headers, received mailbox evidence, founder approval, and sibling lifecycle truth are independent authorities.
- Rejected/deferred “Decompose all of GameSession in one pass”: Rejected. The 5,406-line premise is real, but a wholesale rewrite would destroy the bounded characterization seam. This audit extracts one transaction authority.
- Rejected/deferred “Create synthetic playtest rows to move outcome confidence”: Rejected. The repository has no consented PLAYTESTS cohort and structural tests cannot prove fun, comprehension, or return intent.
- Rejected/deferred “Install a router, schema, or CSP package”: Rejected. Existing dependency-free internal primitives cover the work; no package-trust or supply-chain expansion is justified.
- Rejected/deferred “Edit the sibling registry or owning host repository”: Rejected. Cross-repo truth moves only by signed Studio Ark cargo.

## Three recommended design moves

1. Make every credential operation consume the canonical secrets gateway instead of falling back to a phantom project-local capability map.
2. Ship a deployable, self-validating edge-security policy artifact without claiming the current external host has applied it.
3. Give the Architect Thesis a source-bound checkpoint review with declaration baseline, evidence delta, and exact next action.
